# Staging deployment

Three pieces. The API cannot live on Netlify or Vercel — `server/index.js` runs a
long-lived Express + Socket.IO server and both platforms are serverless, unable
to hold a WebSocket open. That is why `netlify.toml` proxies `/api/*` and
`/socket.io/*` to a separate host.

| Piece | Where | Notes |
|---|---|---|
| API + PostgreSQL | Render — `servisaku-staging-api` | free tier |
| Consumer web | Netlify — publishes `dist/consumer` | `netlify.toml` |
| Partner web | Netlify — publishes `dist/partner` | `netlify.partner.toml` |

## Why there is no render.yaml

A Render Blueprint was tried and rejected:

```
Create database servisaku-db    ✗ cannot have more than one active free tier database
Create web service servisaku-api ✗ canceled: another action failed
```

Render's free tier permits exactly one PostgreSQL instance, and
`servisaku-staging-api` already owns it. A blueprint that cannot create its
database also cannot create the service that depends on it, so the file was
removed rather than left to fail on every push. The service is configured in the
dashboard; this document is the record of that configuration.

If the account moves to a paid plan, a blueprint becomes worthwhile again — it
would need to adopt the existing database rather than declare a new one.

## Render service configuration

**Build command** — `migrate deploy` is what makes the schema match the code. It
only applies committed migrations and never generates new ones, so it is safe on
every boot.

```
npm ci && npx prisma generate && npx prisma migrate deploy && npm run db:seed
```

`db:seed` is included deliberately. The free tier has no shell, so this is the
only way to run it, and it is safe to repeat: every write is an upsert, and the
single `deleteMany` is scoped to one service's question set
(`bookingQuestion.deleteMany({ where: { serviceId } })`), which it immediately
rebuilds. Users, bookings and payments are never touched.

Re-seeding is also how stale localization data is repaired. The category upsert
passes `update: catData`, so a re-run overwrites `nameMy` — which is what fixed
staging serving `name_my: "Beauty & Wellness for Women"`, an English copy left
by a seed predating commit `55faec2`.

**Start command**

```
node server/index.js
```

**Health check path** — `/api/health`

### Environment variables

Required. The server calls `process.exit(1)` at startup if `JWT_SECRET` is
missing or shorter than 16 characters.

| Key | Value |
|---|---|
| `DATABASE_URL` | from the Render database |
| `JWT_SECRET` | generated by Render — never commit or paste one |
| `NODE_ENV` | `production` |
| `CORS_ORIGIN` | both Netlify URLs, comma-separated. The browser is blocked until this matches exactly. |

Staging safety flags:

| Key | Value | Why |
|---|---|---|
| `UNASSIGNED_EXPIRY_ENABLED` | `false` | The worker cancels bookings, voids escrow and issues refunds. Seeded data contains past-dated bookings it would sweep on the first tick. |
| `SMS_DEV_MODE` | `true` | Keeps SMS log-only so nothing real is sent from staging. |

Payment, email and SMS credentials are all left unset. Every one degrades
gracefully: checkout reports the method unavailable, email and SMS no-op, the
chatbot reports itself not ready. **Never put live Billplz or Stripe keys in
staging** — use sandbox credentials if that surface needs exercising, entered in
the dashboard, never in the repository.

## Netlify

Two sites from one repository, because a Netlify site publishes exactly one
directory. Site 2 needs its configuration file path set to
`netlify.partner.toml` under Site settings → Build & deploy.

Both files proxy to the Render host. Four lines, two per file:

- `netlify.toml` — lines 43 and 50
- `netlify.partner.toml` — lines 27 and 33

The partner build is deliberately English-only: `LanguageContext` pins
`SUPPORTED_LANGS` to `['en']` when `VITE_APP === 'partner'`, so a stored `ms`
preference is coerced away rather than honoured, and `apiClient` requests
`en-US`. Verified by grepping the built bundles — `ms-MY` appears in
`dist/consumer` and is absent from `dist/partner`.

## Free tier characteristics

Neither of these is a bug, but both look like one:

- **The API sleeps when idle.** The first request after a quiet period takes
  roughly 50 seconds. A reviewer opening a cold site will think it has hung.
- **Free PostgreSQL is deleted after 30 days.** Fine for a demo; do not put
  anything in it you need to keep.

## Order of operations

`CORS_ORIGIN` cannot be set before the Netlify sites exist, so:

1. Render: set the build command above, deploy, confirm `/api/health` returns
   `{"status":"ok"}`.
2. Repoint the four proxy lines to the Render URL, commit.
3. Deploy both Netlify sites.
4. Set `CORS_ORIGIN` on Render to the two resulting URLs and redeploy.
5. Verify the Malay consumer journey against the live site: category names,
   booking question and option labels, validation copy, chatbot greeting.
